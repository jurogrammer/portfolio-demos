# ScholarSync KR — UI/UX 전문가 리뷰

> 리뷰 대상: https://p10-scholarsync.vercel.app/scholarships?matching=true
> 리뷰 범위: 랜딩, 장학금 검색(전체/매칭), 상세, 프로필, 내 자소서 페이지
> 리뷰 일자: 2026-04-14
> 리뷰어: 10년차 시니어 UI/UX 전문가 관점

---

## 1. 종합 평가

| 항목 | 점수 (10점 만점) | 한 줄 요약 |
|------|:---:|------|
| 정보 설계 (IA) | 7 | 핵심 플로우가 직관적이나, 매칭/필터 간 관계가 불명확 |
| 시각 디자인 | 6 | 깔끔하지만 단조로움. 브랜드 아이덴티티 부재 |
| 인터랙션 | 5 | 피드백 부족, 상태 전환 시 사용자 혼란 가능 |
| 모바일 경험 | 6 | 기본 반응형은 잘 되나, 터치 최적화 미흡 |
| 접근성 | 5 | 시맨틱 구조는 양호하나, 색상 대비/포커스 관리 미흡 |
| 전환율 최적화 | 5 | CTA 경쟁, 가치 전달 부족 |

**총평**: MVP로서 핵심 기능은 잘 작동하지만, "장학금을 찾는 불안한 대학생"의 감정을 고려한 UX 설계가 부족합니다. 정보 밀도가 높은 서비스 특성상 스캔 가능성(scannability)과 의사결정 지원에 더 집중해야 합니다.

## 2. 페이지별 상세 피드백

### 2.1 랜딩 페이지 (`/`)

#### 잘된 점
- "10분이면 충분합니다" — 구체적인 시간 약속이 설득력 있음
- 4가지 핵심 기능을 아이콘+설명으로 명확히 전달
- 통계 섹션(300+, 100+, AI, 무료)으로 신뢰감 확보

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| P0 | **Hero CTA 경쟁** | "장학금 검색하기"와 "무료로 시작하기" 두 버튼이 동등한 시각적 무게로 경쟁 | Primary CTA 1개로 통일. 로그인 상태에선 "장학금 검색하기"만, 비로그인이면 "무료 회원가입" 하나만 표시 |
| P1 | **Hero 영역 시각적 임팩트 부족** | 회색 배경에 텍스트만 존재. 경쟁 서비스(잡코리아, 사람인 장학금) 대비 몰입감 부족 | 장학금 검색 UI의 미니 프리뷰, 또는 실제 사용자 플로우 일러스트 추가 |
| P1 | **통계 수치 신뢰도** | "300+ 등록 장학금"이라고 하지만 실제 검색하면 20개만 나옴 | MVP 단계에서는 실제 수치를 정직하게 표시하거나, 통계 섹션 자체를 제거. 과장된 수치는 신뢰를 깎음 |
| P2 | **로그인 상태에서 불필요한 CTA** | 이미 로그인했는데 Footer에 "회원가입" 링크가 여전히 노출 | 로그인 상태에 따라 Footer 링크 동적 변경 (회원가입 → 프로필 설정) |

### 2.2 장학금 검색 페이지 (`/scholarships`)

#### 잘된 점
- 3-column 그리드 레이아웃이 스캔하기 편함
- D-day 표시로 긴급도 파악 가능
- 기관 유형 뱃지로 빠른 분류 가능

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| **P0** | **"총 20개" 카운트가 매칭 모드에서도 전체 수를 보여줌** | 매칭 ON 상태에서 "총 20개의 장학금이 검색되었습니다" 표시, 실제로는 13개만 보임 | 매칭 모드일 때 "내 프로필에 맞는 13개" 또는 "20개 중 13개 매칭"으로 변경 |
| **P0** | **매칭 토글의 상태 혼란** | 활성화 시 검정 배경의 pill 형태. 비활성 상태의 affordance가 매우 약하고, 처음 방문 시 이 기능이 존재하는지 모를 수 있음 | 매칭 토글을 필터 영역 상단에 토글 스위치로 배치. "내 조건에 맞는 장학금만 보기" 레이블 추가 |
| **P0** | **카드 정보 위계 부족** | 기관명, 장학금명, 금액, 마감일, 학위가 비슷한 시각적 무게로 나열됨 | 금액을 가장 크고 눈에 띄게 (Bold, 색상 강조). 마감 임박 카드는 좌상단에 빨간 뱃지("마감 7일 전") 추가 |
| P1 | **필터와 매칭의 관계 불명확** | 매칭 ON 상태에서 필터를 조작하면 어떻게 되는지 예측 불가. 매칭과 필터가 독립적인지, 교차 적용인지 불분명 | 매칭 모드일 때 필터 영역에 안내 텍스트: "프로필 기반 매칭 결과에 추가 필터를 적용합니다" |
| P1 | **카드 hover 시 피드백 미약** | shadow-md만 추가됨. 클릭 가능하다는 시각적 단서 부족 | hover 시 카드 미세 상승(translateY -2px) + 화살표 아이콘 표시. cursor: pointer는 되어 있으나 시각적 피드백 강화 필요 |
| P1 | **정렬/뷰 옵션 없음** | 마감일순 고정 정렬만 제공 | 정렬 기준(마감일순, 금액순, 최신등록순) 드롭다운 추가. 최소한 마감 임박순/금액 높은순 2가지 |
| P2 | **페이지네이션 없음** | 20개 전부 한 번에 렌더링. 현재는 괜찮지만 데이터 증가 시 문제 | 현재 20건이면 OK. 50건 이상 시 무한스크롤 또는 "더 보기" 버튼 도입 고려 |
| P2 | **빈 상태 디자인** | "검색 결과가 없습니다" 텍스트만 표시 | 일러스트 + "필터를 조정해보세요" + 필터 초기화 버튼을 함께 제공 |

### 2.3 매칭 결과 페이지 (`/scholarships?matching=true`)

#### 잘된 점
- 비로그인 시 매칭 토글이 숨겨져 불필요한 혼란 방지
- 매칭 결과 개수("13개")를 표시하여 필터링이 작동하고 있음을 전달

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| **P0** | **왜 이 장학금이 매칭되었는지 설명 없음** | 그냥 리스트가 줄어들 뿐, 어떤 조건으로 매칭되었는지 사용자가 알 수 없음 | 각 카드에 매칭 이유 태그 추가: "학위 일치", "지역 일치", "학점 충족", "소득분위 충족" 등. 또는 카드 하단에 "4개 조건 중 4개 충족" 같은 매칭률 표시 |
| **P0** | **제외된 장학금에 대한 정보 없음** | 20개 → 13개로 줄었는데, 왜 7개가 빠졌는지 모름 | "프로필과 맞지 않는 7개 장학금 보기" 토글 제공. 제외 사유도 함께 표시 ("학점 미달", "지역 불일치" 등) |
| P1 | **프로필 미완성 시 매칭 정확도 경고 없음** | 프로필에 빈 항목이 있어도 매칭을 그대로 수행 | 프로필 완성도가 낮을 때(예: 50% 미만) 상단에 경고 배너: "프로필을 완성하면 더 정확한 매칭을 받을 수 있어요" + 프로필 편집 링크 |
| P2 | **매칭 토글이 링크(`<a>`)로 구현** | 페이지 전체 리로드 발생. 토글 느낌이 아닌 네비게이션 느낌 | `useRouter`로 클라이언트 내비게이션 처리. 시각적으로도 토글 스위치 UI가 더 적합 |

### 2.4 장학금 상세 페이지 (`/scholarships/[id]`)

#### 잘된 점
- Breadcrumb으로 뒤로가기 경로 명확
- 핵심 정보(금액, 마감일, 접수시작, 대상학위)를 2x2 그리드로 구조화
- "자소서 생성하기" CTA가 상/하 2곳에 있어 접근성 좋음

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| **P0** | **CTA 버튼이 2개 동시 노출 (경쟁)** | 상단 "자소서 생성하기" + 하단 "자소서 생성하기"가 동일 | 상단은 제거하거나 "공식 사이트 바로가기"만 남기고, 하단 자소서 CTA를 유일한 Primary Action으로 강조 |
| P1 | **공식 사이트 링크의 시각적 무게 부족** | 작은 텍스트 링크로만 제공. 지원서 작성을 위해 실제로 가장 중요한 링크 | "공식 사이트에서 지원하기" 버튼을 Secondary 스타일로 격상. 외부 링크 아이콘으로 새 탭 열림 명시 |
| P1 | **지원 요건의 내 프로필 대비 시각화 없음** | "최저 학점: 3.5 / 4.5 이상", "소득 분위: 5분위 이하"만 나열 | 로그인 상태에서 내 학점(3.75)과 비교하여 "충족" 체크 표시. 한눈에 지원 가능 여부 판단 가능 |
| P1 | **자기소개서 문항 영역이 약함** | 제목과 내용만 나열. 이것이 AI 생성의 입력값이 된다는 것을 모를 수 있음 | "이 문항에 맞춰 AI가 초안을 생성합니다" 안내 추가. 각 문항 옆에 글자수 진행 바 등 시각적 요소 |
| P2 | **모바일에서 정보 카드가 세로 1열** | 4개 정보 카드가 세로로 길게 나열되어 스크롤 증가 | 모바일에서도 금액+마감일은 2열, 접수시작+대상학위는 2열로 유지 (2x2 그리드) |

### 2.5 프로필 설정 페이지 (`/my/profile`)

#### 잘된 점
- "학적 정보"와 "자소서 맞춤 정보" 섹션 분리가 명확
- AI 자동입력 기능이 상단에 눈에 띄게 배치
- 각 필드에 예시 텍스트(placeholder)가 상세함

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| **P0** | **폼이 너무 길고 진행 상태 파악 불가** | 스크롤해야 끝이 보이는 긴 폼. 저장 버튼이 맨 아래에만 있음 | 프로필 완성도 프로그레스 바 추가 (상단 고정). "학적 정보 → 관심 분야 → 경험" 단계 표시. 또는 아코디언/탭으로 섹션 분리 |
| P1 | **필수/선택 구분 없음** | 모든 필드가 동일한 시각적 무게. 어디까지 채워야 매칭이 제대로 되는지 모름 | 필수 필드(학교, 학과, 학년, 과정, 학점, 지역, 소득분위)에 * 표시. "이 정보만 채워도 기본 매칭이 가능합니다" 안내 |
| P1 | **저장 피드백이 즉각적이지 않음** | 저장 버튼이 페이지 최하단에만 있어, 상단 수정 후 긴 스크롤 필요 | Sticky 하단 바에 저장 버튼 배치. 변경사항 감지 시 "저장되지 않은 변경사항이 있습니다" 경고 |
| P1 | **자소서 맞춤 정보의 가치 설명 부족** | "아래 내용을 자세히 작성할수록 AI가 더 맞춤화된 자소서를 생성합니다" — 추상적 | 각 필드 옆에 "이 정보가 자소서에 어떻게 활용되는지" 툴팁. 예: 수상경력 → "지원 동기 및 역량 근거로 활용됩니다" |
| P2 | **학점 입력이 자유 텍스트** | 숫자가 아닌 값을 입력할 수 있음. 4.5 만점인데 5.0을 입력해도 저장됨 | 숫자 입력(input type="number") + 선택한 학점 체계에 따른 max 값 제한 + 실시간 유효성 검사 |

#### 개선 필요

| 우선순위 | 이슈 | 현재 | 권장 |
|:---:|------|------|------|
| P1 | **빈 상태(자소서 0개)에 대한 온보딩 부족** | 자소서가 없을 때 빈 화면이 될 가능성 | "장학금을 검색하고 AI로 자소서를 생성해보세요" + CTA 버튼 제공 |

| P2 | **삭제 기능의 접근성** | 리스트에서 바로 삭제할 수 없고 상세 진입 필요 (추정) | 스와이프 삭제(모바일) 또는 호버 시 삭제 아이콘 표시 |

## 3. 크로스커팅 이슈 (전체 서비스)

### 3.1 시각 디자인

| 이슈 | 상세 | 권장 |
|------|------|------|
| **브랜드 컬러 부재** | 전체적으로 흑백+회색 톤. Primary 컬러가 검정 | 교육/장학금 서비스에 맞는 신뢰감 있는 블루 또는 그린 계열 브랜드 컬러 도입. 최소한 CTA 버튼에 포인트 컬러 적용 |
| **카드 디자인 단조로움** | 모든 카드가 동일한 구조와 무게감 | 마감 임박(7일 이내) 카드에 좌측 컬러 바 또는 배경색 변화. 금액 높은 장학금 하이라이트 |
| **아이콘 활용도 낮음** | 텍스트 위주 UI. 시각적 앵커 부족 | 기관 유형별 아이콘(정부, 사설, 지자체), 마감 상태 아이콘 등으로 스캔 가능성 향상 |
| **타이포그래피 위계** | 본문, 라벨, 값의 크기 차이가 작음 | 금액은 text-lg font-bold, 기관명은 text-xs, 장학금명은 text-sm font-semibold로 위계 강화 |

### 3.2 인터랙션 & 마이크로 인터랙션

| 이슈 | 상세 | 권장 |
|------|------|------|
| **로딩 상태 피드백 부족** | 필터 변경 시 전체 페이지 리렌더링, 사용자가 진행 상태 모름 | 카드 그리드에 fade-out/fade-in 트랜지션 또는 skeleton 표시 |
| **토스트 메시지 활용 부족** | 프로필 저장 등 주요 액션에서 피드백 확인 어려움 | 저장 완료, 자소서 생성 시작/완료, 에러 등에 일관된 토스트 사용 |
| **스크롤 위치 복원 없음** | 카드 클릭 → 상세 → 뒤로가기 시 스크롤 위치 초기화 (추정) | Next.js의 scroll restoration 활용 또는 상세를 모달로 처리 |

### 3.3 모바일 경험

| 이슈 | 상세 | 권장 |
|------|------|------|
| **모바일 필터 접근 동선** | "필터" 버튼이 카드 목록 위에 작게 위치. 매칭 토글과 분리되어 있음 | 필터+매칭을 하나의 액션 바로 통합. 상단 고정(sticky) |
| **모바일 카드 터치 영역** | 카드 전체가 링크이지만, 작은 화면에서 카드 간 간격이 좁음 | 카드 간 간격을 gap-4 → gap-3 + py 내부 패딩 증가로 터치 타겟 확보 |
| **모바일 상세 페이지 길이** | 정보 카드 4개가 세로 1열로 길게 나열 | 핵심 정보(금액, 마감일)를 상단에 2열 배치. 나머지는 접이식 |
| **모바일 프로필 폼** | 스크롤이 매우 길어 저장 버튼까지 도달이 어려움 | 하단 고정 저장 버튼(sticky bottom bar) 필수 |

### 3.4 접근성

| 이슈 | 상세 | 권장 |
|------|------|------|
| **매칭 토글의 role 부재** | `<a>` 태그로 구현되어 스크린 리더가 "토글"로 인식하지 못함 | `role="switch"` 또는 실제 토글 컴포넌트 사용 |
| **필터 Select의 라벨 연결** | `<label>`이 시맨틱하게 `<select>`와 연결되지 않음 (id/htmlFor 미사용) | 각 필터에 고유 id 부여 후 label의 htmlFor 연결 |
| **색상 대비** | `text-muted-foreground`가 배경 대비 약할 수 있음 (특히 밝은 테마) | WCAG AA 기준(4.5:1) 충족 검증 |
| **키보드 내비게이션** | 카드 그리드에서 탭 키 이동 시 포커스 표시 미확인 | focus-visible 스타일 확인 및 강화 |

## 4. 사용자 여정 관점 개선 제안

### 현재 사용자 플로우
```
랜딩 → 회원가입 → 프로필 작성 → 장학금 검색 → 매칭 토글 → 상세 보기 → 자소서 생성
```

### 문제점
1. **프로필 작성이 너무 이른 단계에서 요구됨** — 사용자가 서비스 가치를 체감하기 전에 긴 폼 작성을 요구
2. **매칭 기능 발견이 어려움** — 처음 방문 시 매칭 토글의 존재를 모를 수 있음
3. **자소서 생성까지의 거리가 멈** — 5단계를 거쳐야 핵심 가치에 도달

### 권장 플로우
```
랜딩 → 장학금 검색(비로그인) → 관심 장학금 발견 → 자소서 생성 시도 → 회원가입 유도
→ 최소 프로필(학교, 학과, 학년만) → 자소서 생성 → 매칭 추천 → 프로필 보강
```

**핵심 원칙**: "가치 체감 → 가입 → 점진적 정보 수집"
